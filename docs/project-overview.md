## 1. 최신 PRD (2026-08-11 전달분 — **이것이 최신**)

**한 줄 정의**: SNS를 통해 챌린지 신청과 모집 과정을 거칠 필요 없이, 조건이 맞는 6명을 자동 랜덤 매칭하여 작심삼일 문제를 해결해 주는 실시간 목표 달성 케어 서비스.

**제품 목표**
- 직접 팀원을 모집하거나 SNS 챌린지를 신청하는 번거로움을 제로화하고, 원하는 목표 시간과 관심사가 유사한 6명을 원클릭으로 랜덤 매칭한다.
- 혼자서는 포기하기 쉬운 10~30대가 가벼운 소규모 그룹 내에서 상호 인증·응원을 주고받으며 끝까지 완주하도록 독려한다.

**배경**: 기존 SNS 챌린지는 신청 절차 부담, 낯선 사람과의 관계 형성 부담, 혼자 인증을 이어가기 어려운 외로움 때문에 시작조차 망설이거나 중도 포기한다. 모집·개설이 필요 없는 6인 랜덤 그룹과 정해진 기간으로 참여 장벽을 낮춘다.

**핵심 지표 6종**
| 지표 | 정의 | 측정 원천(구현) |
|---|---|---|
| 매칭 완료율 | 매칭 요청자 중 6인 그룹 배정 완료 비율 | `match_event(MATCH_COMPLETED)` |
| 매칭 대기 이탈률 | 대기 중 취소·만료로 종료한 비율 | `match_event(WAIT_CANCELLED/WAIT_EXPIRED)` |
| 첫 인증 완료율 | 매칭 완료자 중 첫 인증 완료 비율 | `proof` 최초 행 |
| 정식 완주율 | 종료 시점 참여자 중 개인·그룹 이중 기준 충족 비율 | `completion_stats` |
| 30일 재참여율 | 리포트 확인 후 30일 내 새 매칭 시작 비율 | `match_event(REJOIN_ENTRY)` |
| 신고 처리 준수율 | 고위험 24h·일반 72h 내 판단 완료 비율 | `report_case.sla_due_at`·`report_history` |

**리스크(원문)**: ① 탈퇴 30일 유예 후 자동 삭제 누락 점검 ② 법령상 별도 보관 기록의 대상·기간 확정 ③ 기한 초과 신고 관리·임시 이용 제한

**속성**: 카테고리 생산성/업무 · 역할 참여자·운영관리자 · 기기 Android/iOS/PC-Web
→ **기기 3종은 "앱 3개"가 아니라 접속 환경.** 실제 구현은 **반응형 웹앱 1개 + Spring 백엔드 1개**

## 2. 요구사항 7영역 × 기능 17개 — 원문 ↔ 구현 매핑

각 기능마다 **원문 요구 / 구현(API·테이블) / 구현 단계 / 애매한 것**을 적었다.

### 영역 1. 온보딩 및 연령 확인
> 만 14세 이상만 참여. SNS가 생년월일을 안 주면 직접 입력받아 검증. 미만은 매칭·인증 차단.

| 기능 | 원문 핵심 | 구현 | 단계 | 애매한 것 |
|---|---|---|---|---|
| 1-1 SNS 소셜 로그인 가입 | 4종 SNS·1~2탭 온보딩. **데이터: 식별자·프로필 이미지·닉네임·생년월일 저장** | `AU-1` + `member` | 1(뼈대)·11(카카오 실연동) | ⚠ **프로필·닉네임을 저장하지 않기로 바꿈**(실명 노출 위험) → 승인 필요 |
| 1-2 생년월일 입력·연령 검증 | 만 14세 계산, 미만이면 가입 유지+기능 차단 | `AU-3` + `member.birth_date·age_verification` | 1 | — |
| 1-3 미성년 참여 제한 안내 | 제한 사유·**재시도 불가**·문의처 | 전역 인터셉터 403 `AGE_NOT_VERIFIED` | 1 | 게시판 열람은 허용했는데(안전 도구인 신고도 허용) 이게 "챌린지 관련 화면 접근 거부"에 걸리는지 |

### 영역 2. 조건 기반 6인 자동 매칭
> 조건 3개 선택 → 동일 조건 6명 즉시 그룹. 대기·성사·실패(시간 초과) 상태 관리.

| 기능 | 원문 핵심 | 구현 | 단계 | 애매한 것 |
|---|---|---|---|---|
| 2-1 매칭 조건 선택 | 분야·하루 목표 시간·기간 3단계. **선행: 연령 검증 통과** | `MT-1` + `match_request` | 2 | 기간 = **30/60/100일**(팀장 확정). 와이어프레임은 7/14/21/30 → 프론트 교체 필요 |
| 2-2 자동 랜덤 매칭 엔진 | 동일 조건 6명 → 즉시 그룹. **전원에게 알림 발송**·그룹 채팅 활성화 | `MT-1` 내부 + `challenge_group`·`group_member`·`match_lock` | 2 | ⚠ **알림 미구현**(승인 필요) / **채팅은 없음**(팀장 확정) / **시작일 언제인지 미정** |
| 2-3 매칭 대기 및 취소 | 대기 현황(4/6)·**예상 대기 시간**·취소·**유효 기간 만료 자동 종료** | `MT-2`·`MT-3` + `B2` 배치 | 2 | ⚠ **예상 대기 시간 필드 없음** / 만료 24h는 잠정 / **6명이 안 모일 때 완화책 없음** |

### 영역 3. 챌린지 실천 및 인증
> 설정된 시간대에 캠 또는 사진으로 인증. 같은 그룹에만 공개. 스티커로 응원. 대시보드.

| 기능 | 원문 핵심 | 구현 | 단계 | 애매한 것 |
|---|---|---|---|---|
| 3-1 캠/사진 실천 인증 | 인증 시간대 내 제출, **마감 초과 거부**, **하루 최초 1건만 인정**, 그룹 피드 노출 | `PF-1`·`PF-2` + `proof`·`proof_media` | 4 | ⚠ **"설정된 인증 시간대"의 주체 불명**(현재 06:00~23:59 고정 잠정) / **얼굴 나오면 거부**로 정함(승인 필요) |
| 3-2 응원 스티커 | 스티커만(텍스트 없음), **중복 시 토글 취소**, 작성자에게 **알림** | `ST-1`·`ST-2` + `sticker_reaction` | 5 | ⚠ 응원 알림 미구현 |
| 3-3 그룹 대시보드 | 본인·6명 일자별 인증·누적 달성률. **달성률 = 인증 일수 / 전체 기간** | `DB-1` | 6 | 타 멤버의 누적 달성률 필드가 응답에 없음(클라 계산 필요) |

### 영역 4. 자율 퇴장 및 안전 신고
> 사유 선택 즉시 퇴장. 신고하면 접수와 동시에 그룹 접근 차단.

| 기능 | 원문 핵심 | 구현 | 단계 | 애매한 것 |
|---|---|---|---|---|
| 4-1 자율 퇴장 | 사유 선택 → 즉시 퇴장, 운영자 승인 불필요. **인원이 기준 미만이면 완주 판정 별도 기준** | `GR-3` + `group_member.LEFT` | 3 | ⚠ **"기준 미만"이 몇 명이고 별도 기준이 뭔지 원문에 없음** — 지금은 오히려 더 가혹함 |
| 4-2 신고 및 즉시 접근 차단 | 신고 접수 = **신고자 그룹 접근 즉시 차단**, 고위험/일반 분류, **중복은 1케이스 병합** | `RP-1` + `report_case`·`report` | 9 | ⚠ **"신고자 접근 차단"이 퇴장인지 뮤트인지** — 퇴장이면 신고=내 챌린지 포기가 되고 악용 여지 |

### 영역 5. 완주 리포트 및 재참여
> 종료 시각 AI 1차 판정 → 리포트 → 재참여 진입.

| 기능 | 원문 핵심 | 구현 | 단계 | 애매한 것 |
|---|---|---|---|---|
| 5-1 완주 판정 및 결과 리포트 | 개인 리포트(달성률·인증 기록·완주 여부) + 그룹 리포트(멤버별 요약). **완주 배지·기여도 표시** | `FR-1` + `B1` 배치 + `final_report`·`completion_stats` | 8 | ⚠ **완주 기준값 미정**(개인 %·그룹 %) / **배지 등급 규칙을 임의로 정함** / "기여도" 정의 없음 |
| 5-2 재참여 유도 | 리포트 → 조건 선택 화면 이동 | `MT-1`의 `rejoinFromGroupId` + `match_event` | 2·8 | — |

| 기능 | 원문 핵심 | 구현 | 단계 | 애매한 것 |
|---|---|---|---|---|

| 7-2 AI 부적절 콘텐츠 사전 검열 | 이미지(선정·폭력·**얼굴**·신분증·차량번호) + 텍스트(폭언·협박·스팸), 고위험 차단 후 관리자 큐 | `PF-2` 2단계 + 텍스트는 신고 상세·게시글 소감 | 4·7 | ⚠ **얼굴 탐지 ↔ 캠 인증이 원문끼리 충돌** / 차단물 보관 규칙이 원문에 없음 |
| 7-3 AI 완주 판정 자동화 | 종료일 자정 자동 판정, 명확하면 확정, **경계값만 에스컬레이션** | `B1` 배치 + `AD-7` 큐 | 8 | ⚠ 완주 기준값·경계 폭 미정 |

| 4 | **알림은 매칭 완료 1종만** v1에 포함 | 대기 화면 폴링 + 재진입 배너. 푸시·응원 알림·리마인더는 v2 |
| 5 | **AI 관련성 판정도 실제 차단까지 수행** (AI가 서비스 핵심이므로) | 7단계 초기엔 로깅만 하며 임계값을 잡고, 잡히면 차단 켬 |
| 6 | **SNS 프로필·닉네임은 원문대로 저장**하되, **타인에게 보이는 화면엔 익명 닉네임만 노출** | 저장(요구1-1)과 실명 비노출을 둘 다 만족. 탈퇴 시 SNS 값 삭제(요구6-3) |

### ⛔ 아직 팀장 확인이 필요한 것 (4)

1. **자격증 시험 날짜 챌린지** — 앱이 시험 목록 제공? 자유 입력?(자유 입력은 6인 매칭 구조상 불가) ⭐2단계 전 필요
2. **완주 기준** — 개인 몇 %? 그룹 몇 %? **그룹 기준을 꼭 넣나?**(내가 100% 해도 남 때문에 미완주가 됨)
3. **인원 줄면** — 몇 명 미만부터 어떤 기준으로?(원문 요구4-1이 요구했으나 값이 없음)
4. **매칭 안 될 때** — 조건 완화·대기 연장을 v1에 넣을지

## 4. 와이어프레임 24장 — 어떻게 할 것인가

24장은 **기능명세서가 개정되기 전**에 만들어졌다. 그 사이 확정된 변경(기간 30/60/100, 충원 폐지, 연령 검증·자율 퇴장·탈퇴·게시판 신설, 얼굴 거부)이 반영돼 있지 않다. 전수 대조 결과:

- ✅ 그대로 가능 2장 / ⚠️ 부분 수정 14장 / ❌ 값·문구 충돌 6장 / 💀 **폐기 2장**(23 공석 관리·24 충원 완료 — 충원 기능이 없어짐)
- **없어서 새로 만들어야 할 화면 15종**: 생년월일 입력·미성년 안내·촬영물 동의·자율 퇴장·탈퇴·게시판 3종·공유 카드·AI 상태 배지·SLA 콘솔 등
- **값 교체 8건**: 기간 칩 7/14/21/30 → 30/60/100, 분야 라벨 통일, 신고 상태에 "제재" 추가, 서비스명 `작심6`→`모락` 등

**대응 방침**: 백엔드는 24장에 맞추지 않고 **정본(API 명세서)대로 만든다.** 화면 쪽 수정 목록을 `docs/프론트_수정요청_통합.md`로 정리해 프론트에 전달하고, 백엔드가 응답 필드를 추가해야 하는 5건(홈 달성률·관리자 집계·예상 대기 시간 등)만 회수해서 검토한다.

## 5. 진행 상황

```
✅ 0단계   프로젝트 뼈대 + 공통 에러 계약   (빌드·404 게이트 실측 통과)
▶ 0.5단계  enum 정정 + 에러코드 + 설정      ← 다음 작업
  1단계    회원·연령검증·JWT·제재조회
  2단계    ★매칭 엔진        [시작일 확정 필요]
  3~7단계  그룹·인증·대시보드·AI
  8단계    완주 판정         [완주 기준 확정 필요]
  9·9.5    신고·제재·게시판   [신고자 처리 확정 필요]
  10·11    탈퇴·배포
```

**검증**: 문서 13라운드 + 원천 대조 완료(`docs/검증기록`). 이후 검증은 단계별 curl 게이트가 수행한다.

**규칙**: 한 단계 = 한 커밋. 게이트 통과 없이 다음 단계로 가지 않는다. 커밋·푸시는 화수가 직접 한다.
