# 모락(Morak) 기능명세서 v4 — 요구 정본 (2026-08-12)

> **요구 정본.** 팀에서 받은 원문은 `원천자료_기능명세서_원문.md`(가공 없음), 원문 대비 변경과 그 승인 상태는 `원문대비_변경승인요청.md`에 있다. 계약은 `API명세서_모락_v1.0.md`.
> 와이어프레임은 기존 24화면 기반 유지(화수 지시). 원문의 오탈자("캐"→캠, 일부 깨진 문장)는 의미 보존 범위에서 정정 표기.

## PRD 변경 요점 (개요)

- **연령 제한 신설**: 만 14세 이상만 참여. SNS에서 생년월일 미수신 시 직접 입력으로 검증. 미만은 매칭·인증 차단
- 핵심 지표 확정 6종: 매칭 완료율 / **매칭 대기 이탈률** / 첫 인증 완료율 / 정식 완주율(이중 기준) / 30일 재참여율 / **신고 처리 목표 준수율(고위험 24h·일반 72h)**
- 리스크 명시: 탈퇴 30일 유예 후 자동 삭제 누락 점검 / 기한 초과 신고 관리·임시 이용 제한
- 페르소나(김도윤): "아무도 검수하지 않는 인증 앱은 3일만에 이탈" → **AI 인증 진위 판별의 근거**
- 프리미엄 구독(월 4,900원)은 **가설 단계** — 기능 아님
- 카테고리: 교육/학습 → 생산성/업무

## 영역 1. 온보딩 및 연령 확인

### 1-1. SNS 소셜 로그인 가입 (8/8)
- SNS 계정 간편 가입·로그인. 제공자로부터 프로필·식별자·(가능 시) 생년월일 수신, 1~2탭 온보딩
- 성공 기준: 가입 시작 대비 완료율
- 트리거: 최초 실행 'SNS로 시작하기' / 동작: 인증 완료 후 계정 생성 또는 로그인 / 예외: 인증 실패·취소 시 가입 화면 복귀+오류 안내
- 권한: 비로그인만 접근, 완료 시 참여자 권한 / 데이터: SNS 식별자, **서버 생성 익명 닉네임**, (제공 시) 생년월일. **SNS 닉네임·프로필 이미지는 저장하지 않는다**(익명 보호)

### 1-2. 생년월일 직접 입력 및 연령 검증 (8/8) ★신규
- SNS에서 생년월일 미수신 시 가입 과정에서 직접 입력 → 만 14세 이상 계산
- 트리거: 가입 직후 생년월일 미보유 확인 시 자동 노출
- 결과: 검증된 생년월일 저장 + 연령 검증 상태 '완료'
- 예외: 만 14세 미만 → **가입은 유지하되 매칭·인증 접근 차단** + 제한 안내 이동
- 규칙: 만 14세 이상만 매칭·인증 접근 / 데이터: 검증된 생년월일(수정 가능 여부는 정책 별도)

### 1-3. 미성년자 참여 제한 안내 (6/6) ★신규
- 만 14세 미만 판정 시 제한 사유·재시도 불가·문의처 안내. 챌린지 관련 화면 접근 거부

## 영역 2. 조건 기반 6인 자동 매칭

### 2-1. 매칭 조건 선택 (7/7)
- **선행조건: 연령 검증 통과** (신규 조건). 분야·하루 목표 시간·기간 3단계 선택 → 대기열 등록
- 예외: 조건 미완성 시 시작 불가 / 데이터: 조건 3종+요청 시각

### 2-2. 자동 랜덤 매칭 엔진 (7/7)
- 동일 조건 6명 확보 시 즉시 그룹 생성·배정. 트리거: **신규 요청 등록 시마다 재계산**
- 결과: 그룹 생성 + 전원에게 매칭 완료 통지(알림 채널은 v1 미구현 — 클라이언트 폴링) + 그룹 인증 공간 활성화. **자유 텍스트 채팅은 제공하지 않는다(팀장 확정 2026-08-11)**
- 규칙: 정확히 6명, 동일 조건만 / 데이터: 그룹 ID, 6명, 조건, 생성 시각, 시작·종료일

### 2-3. 매칭 대기 및 취소 (6/6) ★대기 만료 신규
- 대기 현황(예: 4/6명)·**예상 대기 시간** 표시, '대기 취소' 즉시 종료
- **대기 유효 기간 만료 시 자동 종료 + 재시도 안내** (기간 값 미정)
- 지표: 매칭 대기 이탈률

## 영역 3. 챌린지 실천 및 인증

### 3-1. 캠/사진 실천 인증 (8/8)
- **"설정된 인증 시간대"에** 캠 또는 사진으로 인증 ⚠(시간대 정의·설정 주체 미정 — N-Q2)
- 예외: **인증 시간 경과 후 업로드 → '당일 인증 마감 초과' 거부** / **하루 복수 제출 → 최초 1건만 공식 인정** (v2 Q4 해소)
- 공개 범위: 같은 그룹 멤버만("그룹 피드") / 데이터: 인증 ID, 작성자, 그룹, 미디어, 시각
- ⚠ v2의 촬영물 동의·30일 보관·관리자 열람 조항이 본 판에 **없음** — 유지 여부 N-Q3

### 3-2. 응원 스티커 (6/6) ★동작 변경
- 인증 카드에 스티커, **중복 응원 시 기존 응원 취소(토글)** — v2의 "멱등·집계 불변"에서 변경
- 결과: 작성자에게 **응원 알림** / 지표: 인증당 평균 응원 수

### 3-3. 그룹 대시보드 (8/8) ★계산식 변경
- 본인·6명 일자별 인증·누적 달성률. **달성률 = 완료 인증 일수 ÷ 전체 챌린지 일수** — v2의 "경과 일수" 분모에서 변경
- 지표: 대시보드 일평균 방문

## 영역 4. 자율 퇴장 및 안전 신고 ★영역 신설 (v2는 자율 퇴장 명시적 배제였음)

### 4-1. 자율 퇴장 (7/7) ★신규
- 사유 선택 → **운영자 승인 없이 즉시 퇴장**. 그룹 접근 상실, 멤버 수 감소
- 예외: **인원이 기준 미만이 되면 공식 완주 판정 기준을 별도 적용** (기준값 미정 — N-Q4. **충원 언급 없음**)
- 데이터: 퇴장 이력(사유·시각)

### 4-2. 신고 및 즉시 접근 차단 (9/9) ★메커니즘 변경
- 신고 제출과 **동시에 신고자 본인의 그룹 접근 즉시 차단** (운영자 개입 없이 시스템 처리)
- 신고 건은 **고위험/일반** 구분으로 운영 대기열 등록. **동일 건 중복 신고는 1케이스로 병합**
- 처리 상태: **미처리/처리완료/기각/제재** (v2의 4상태 대체)
- 권한: 신고 상세는 운영관리자만 / 데이터: 신고 ID, 신고자, 피신고자, 대상 그룹/인증, 유형, 시각, 상태

## 영역 5. 완주 리포트 및 재참여

### 5-1. 완주 판정 및 결과 리포트 (7/7) ★판정 주체·시점 변경
- **챌린지 종료 시각에 AI가 1차 자동 판정**(영역 7-3) → 리포트 생성·제공 (v2의 "첫 호출 시 계산"에서 변경)
- 리포트: 개인(달성률·인증 기록·완주 여부·완주 배지) + 그룹(멤버별 요약·기여도)
- 지표: 정식 완주율 / 데이터: 리포트 ID, 챌린지 ID, 개인·그룹 완주 여부, 생성 시각

### 5-2. 리포트 기반 재참여 유도 (4/4)
- '다음 챌린지 시작하기' → 조건 선택 화면 즉시 이동 / 지표: 30일 재참여율

## 영역 6. 운영 관리자 도구 ★탈퇴·SLA 신설, 퇴장·충원 부재

### 6-1. 신고 처리 콘솔 (6/6)
- 고위험/일반 구분 목록 → 처리완료·기각·**제재** 확정. **제재 시 대상 사용자에게 이용 제한 적용** (v2의 그룹 퇴장 조치 대체)

### 6-2. 신고 SLA 모니터링 (6/6) ★신규
- 고위험 24h/일반 72h 초과 건 자동 분류 + **임시 이용 제한 검토 플래그** + 관리자 알림·전용 필터 목록

### 6-3. 탈퇴 유예 및 자동 삭제 관리 (9/9) ★신규 (v2에 탈퇴 자체가 없었음)
- 탈퇴 신청 → **30일 유예** → 종료 시 SNS 식별자·검증 생년월일·프로필 **자동 삭제**, 계정 '삭제완료', 운영 로그
- 예외: 유예 중 재로그인 시 철회·복구 가능(30일 경과 후 불가)
- 데이터: 신청 계정, 신청·예정 삭제·완료 시각

## 영역 8. 완주 자랑 게시판 및 외부 공유 ★팀장 요구 추가 (2026-08-11) — 매니패스트 명세 외, 팀 결정으로 편입

> 출처: 팀장 구두 요구("챌린지 달성 게시판에 자랑할 수 있게" + "인스타그램 공유 기능"). 매니패스트 v3 원문에는 없으며 **팀 결정으로 v1 범위에 편입**. 이 시점으로 v1 요구사항 동결.

### 8-1. 완주 자랑 게시글 작성·열람 (PB-1~3, PB-5)
- 챌린지 **종료 후** 참여자가 자신의 완주 결과(달성률·완주 여부·배지)를 앱 내 공개 게시판에 올려 자랑한다. **그룹당 1건**
- **게시 가능한 것은 리포트 수치 + 한 줄 소감(200자)뿐 — 인증 사진은 게시 대상이 아니다**(얼굴 차단·같은 그룹만 열람·종료 후 열람 차단·30일 삭제 정책 보호)
- 수치는 시스템이 완주 리포트에서 복사해 저장(사용자 수정 불가 — 자랑의 신뢰성)
- 작성자는 익명 닉네임으로 표시. 로그인 사용자만 열람
- 근거: 완주 성취를 가시화해 재참여(30일 재참여율)와 신규 유입을 높인다

### 8-2. 응원(좋아요) — PB-4
- 게시글에 좋아요 토글. **댓글은 제공하지 않는다**(PRD "친목 없는 저부담 관계" 유지, 자유 텍스트 검열 부담 최소화)

### 8-3. 외부 공유 (인스타그램 등)
- 게시글·완주 리포트를 **이미지 카드로 만들어 외부 SNS에 공유**. 이미지 생성·공유는 **클라이언트가 수행**(Web Share API), 백엔드는 조회 데이터만 제공 — 서버 이미지 렌더링 없음
- 공유 횟수 지표는 v2 백로그

### 8-4. 안전 (신규 관리 기능 없음 — 기존 체계 재사용)
- 게시글 신고는 기존 신고 체계에 대상 유형 `POST` 추가로 처리(케이스 병합·고위험/일반 SLA 동일)
- 한 줄 소감은 **AI 텍스트 검열 대상**(영역 7-2의 텍스트 경로 2곳 중 하나(다른 하나는 신고 상세))
- 관리자 비노출·복구는 기존 인증 비노출 기능(AD-6) 확장으로 처리
- ⚠ 신고 시 "신고자 즉시 그룹 접근 차단"(4-2)은 게시글 신고에는 적용하지 않는다 — 게시글은 그룹 소속과 무관

## 영역 7. AI 실시간 판단 엔진 ★영역 신설 — AI 1곳 → 3곳으로 확장, "서비스 핵심 엔진"으로 격상

공통 원칙: AI는 1차 판단자. **확신도 낮음·고위험만 운영관리자 에스컬레이션**, 명확한 건은 단독 확정.

### 7-1. AI 인증 진위 판별 (9/9) ★신규
- 업로드 즉시: ① 목표 분야와의 **관련성 점수** 계산 ② **이미지 해시로 과거 인증 재사용 대조** ③ 도용·무관 피사체 탐지
- 결과: 기준치 이상 → 통과·공개 / 미달 → **보류**(재업로드 안내 또는 관리자 대기열) / 애매 구간만 에스컬레이션
- 표시: 인증 카드에 상태 배지(통과/확인중/보류). 판단 근거(확신도·사유)는 관리자만
- 데이터: 판단 ID, 인증 ID, 결과(통과/보류/거부), 확신도, 사유, 시각
- ⚠ 관련성 기준치·확신도 임계값 미정 — N-Q5

### 7-2. AI 부적절 콘텐츠 사전 검열 (9/9) — v2 "유해 화면 감지"의 확장판
- **모든 업로드 콘텐츠(이미지+텍스트)를 공개 전 예외 없이 검사**: 선정·폭력·**식별 가능 개인정보(얼굴·신분증·차량번호)** / 텍스트(신고 상세·게시글 소감) 폭언·협박·스팸
- 고위험 → 공개 차단 + 관리자 대기열. 차단자에겐 '검토 중'만 표시(사유 비노출). 복구는 관리자 검토로만
- 데이터: 검열 ID, 콘텐츠 ID, 위험 유형, 차단 여부, 시각

### 7-3. AI 완주 판정 자동화 (8/8) ★신규
- 종료일 자정 자동 실행: 개인 인증률·그룹 평균 계산 → 이중 기준 **명확 충족/미달은 AI 단독 확정** → 리포트 즉시 생성
- **임계치 근접(경계값)만 관리자 대기열로 에스컬레이션**
- 데이터: 판정 ID, 챌린지 ID, AI 판정, 관리자 확정 여부, 시각
