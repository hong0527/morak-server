## 2. 화면별 상세

### 1. 온보딩 화면
- **설명(우측 패널)**: 앱 최초 진입 화면. 서비스 소개 후 가입/로그인으로 분기. 회원가입 완료 시 조건 선택 매칭 화면으로, 로그인 완료 시 홈으로 이동.
- **표시 데이터**: 모락 로고(placeholder), 타이틀 "모락", 부제 "모여서 함께 몰입하는 6인 챌린지", 소개 카드 3개 — ① "목표만 정하면 끝 / 분야·시간·기간을 선택하면 익명 동료 5명과 자동 매칭" ② "매일 한 장의 인증 / 사진 또는 실시간 캠으로 오늘의 실천을 기록한다" ③ "응원 스티커로 서로 힘을 주고받기 / 텍스트 채팅 없이 인증과 응원에만 집중한다"
- **버튼/액션**: [회원가입 시작하기], [이미 계정이 있어요 — 로그인]
- **다음 경로**: 로그인 화면, 회원가입 화면
- **필요 API**: 없음(정적)

### 2. 회원가입 화면
- **설명**: SNS 원클릭 가입(카카오·네이버·구글·애플). "추가 정보 입력은 프로필 설정 단계로 분리한다. 회원가입 완료 후 프로필 설정 화면으로 이동한다."
- **표시 데이터**: 타이틀 "회원가입", 부제 "SNS 계정으로 가입하기"
- **버튼/액션**: [카카오로 시작] [네이버로 시작] [구글로 시작] [애플로 시작], [로그인] 링크, [<] 뒤로
- **다음 경로**: 로그인 화면 (이전: 온보딩)
- **필요 API**: AU-1 (isNewMember=true 경로)
- **주의**: 설명문이 말하는 "프로필 설정 화면"은 24장 안에 **존재하지 않음** → AU-3을 쓸 화면이 없음 (§3(b), (c) 참조)

### 3. 로그인 화면
- **설명**: 기존 사용자 SNS 로그인. 완료 시 홈으로 이동.
- **표시 데이터**: 타이틀 "작심6에 로그인"(주: 앱명이 온보딩의 "모락"과 다름), 부제 "SNS 계정으로 간편하게 시작하세요"
- **버튼/액션**: [카카오로 로그인] [네이버로 로그인] [구글로 로그인] [애플로 로그인], [회원가입] 링크, [<]
- **다음 경로**: 홈 화면
- **필요 API**: AU-1

### 4. 홈 화면
- **설명**: 진행 중 챌린지 그룹 현황 확인 또는 새 챌린지 매칭 시작. 핵심 기능(인증·응원·성과 리포트) 소개.
- **표시 데이터**: 인사 문구 "오늘도 작심6과 함께 / 6명이 함께, 부담 없이 목표를 완주하세요", **진행 중인 챌린지 카드**: "D-18 · 독서", "18일째 인증 중 · 달성률 72%", **작심6 핵심 경험** 소개 이미지+카드(매일 인증 / 응원 스티커), **성과 리포트 요약**: 내 인증 일수 "18일 완료", 달성률 "72%", 그룹 달성 "흐름 확인 →", 하단 탭바: 홈/매칭/그룹/리포트/관리
- **버튼/액션**: [그룹 확인], [새 챌린지 시작하기], [흐름 확인 →], 하단 탭 5개
- **다음 경로**: 운영관리자 홈, 챌린지 조건 설정 화면
- **필요 API**: GR-1(진행 중 그룹·category·endDate→D-day), DB-1(달성률·인증 일수)
- **갭**: GR-1 응답에는 달성률·인증 일수가 없음 → 홈 요약을 만들려면 그룹별 DB-1을 추가 호출해야 함(조합). 홈 요약 전용 API는 미커버(우회 가능)

### 5. 챌린지 조건 설정 화면
- **설명**: 목표 분야·하루 목표 시간·챌린지 기간 3개 조건 선택 시 매칭 시작 버튼 활성화. 매칭 요청 시 매칭 대기 화면으로.
- **표시 데이터**: **목표 분야 칩**: 운동/공부/독서/식단/수면/기타, **하루 목표 시간** 드롭다운(표시값 "30분"), **챌린지 기간 칩**: 7일/14일/21일/30일, **선택한 조건 요약**(목표 분야—/하루 목표 시간—/챌린지 기간—)
- **버튼/액션**: [매칭 시작하기], [조건 누락 안내로 돌아가기], 하단 탭(매칭 활성)
- **다음 경로**: (잘려서 일부 확인 불가; 이전 경로: 홈·조건 누락 안내·조건 조정 안내·챌린지 결과 리포트)
- **필요 API**: MT-1
- **갭**: 화면 분야 목록(운동/공부/독서/식단/수면/기타) ↔ API enum `GoalCategory { STUDY, EXAM, LANGUAGE, EXERCISE, READING }` 불일치(식단·수면·기타 없음, EXAM·LANGUAGE는 화면에 없음) — [Q9] 확정 필요. 기간 30일·21일은 API가 "서비스에서 검증"이라 목록 확정만 필요

### 6. 조건 누락 안내 화면
- **설명**: 필수 조건 미선택 시 진행 불가 안내. 누락 조건 명시 후 조건 설정으로 복귀.
- **표시 데이터**: "필수 조건을 선택해주세요 / 다음 항목이 아직 선택되지 않았습니다", 누락 목록: 목표 분야·하루 목표 시간·챌린지 기간
- **버튼/액션**: [조건 설정으로 돌아가기], [<]
- **다음 경로**: 챌린지 조건 설정 화면
- **필요 API**: 없음(클라이언트 검증)

### 7. 매칭 대기 화면
- **설명**: 자동 매칭 진행 중 조건과 대기 상태 확인. 조건 조정 또는 재선택 가능. (명세서 MT-2가 "와이어프레임 #7 폴링"으로 지목한 화면)
- **표시 데이터**: "매칭 진행 중 / 익명 동료를 찾고 있어요", **내 매칭 조건**(목표 분야 "자기계발", 하루 목표 시간 "1시간", 챌린지 기간 "21일"), **현재 모집 현황**("참여 확정 3 / 6명", 안내문), **예상 대기 시간**("약 2~5분", "대기 중 앱을 닫아도 매칭이 완료되면 알림을 드려요")
- **버튼/액션**: [매칭 완료 확인하기], [조건 조정하기], [조건 다시 선택하기], [<]
- **다음 경로**: 조건 조정 안내 화면, 매칭 완료 알림 화면
- **필요 API**: MT-2(폴링), 조건 변경 시 MT-3→MT-1
- **미커버**: ① "참여 확정 N/6명" — MT-2 응답(matchRequestId/status/requestedAt/groupId)에 없음 ② "예상 대기 시간" — 없음 ③ "내 매칭 조건" 표시 — MT-2에 category/dailyTargetMinutes/periodDays 없음(클라 로컬 보관으로 우회 가능하나 새로고침 시 유실) ④ "앱을 닫아도 알림" — 푸시 알림, 명세서는 MVP 제외 권장. 화면의 [조건 조정]은 **MT-3(명세 외, Q7)이 필수임을 뒷받침**

### 8. 조건 조정 안내 화면
- **설명**: 매칭 장기화 시 표시. 조건 조정 또는 현재 조건 유지 선택. 조정 시 조건 설정 화면으로, 유지 시 대기 화면으로.
- **표시 데이터**: "매칭이 조금 오래 걸리고 있어요 / 현재 조건에 맞는 참여자를 찾는 중인데 인원이 부족해요...", **현재 매칭 조건**(목표 분야 "운동 / 헬스", 하루 목표 시간 "30분", 챌린지 기간 "21일"), **추천 카드** "이런 조건은 어떨까요? / 기간을 14일로 줄이거나 하루 목표 시간을 20분으로 낮추면 지금 바로 매칭될 수 있어요."
- **버튼/액션**: [조건 조정하기], [지금 조건으로 계속 대기하기], [<]
- **다음 경로**: 매칭 대기 화면, 챌린지 조건 설정 화면
- **필요 API**: MT-3 + MT-1(조정), MT-2(유지 시 계속 폴링)
- **미커버**: 대기 장기화 감지 신호와 **완화 조건 추천**("지금 바로 매칭될 수 있어요" = 대기열 통계 기반 추천) — 명세서에 해당 데이터/엔드포인트 전혀 없음

### 9. 매칭 완료 알림 화면
- **설명**: 6인 매칭 완료 알림. 조건·그룹 정보 요약 후 그룹 입장.
- **표시 데이터**: "매칭 완료! / 익명 동료 5명과 연결되었어요", **내 챌린지 조건**(자기계발/1시간/21일), **그룹 정보**(그룹 인원 "6명", 시작일 "2025년 7월 14일", 종료일 "2025년 8월 3일"), 안내문 "그룹 내에서는 인증과 응원 스티커로만 소통해요. 자유 채팅은 제공되지 않아요."
- **버튼/액션**: [챌린지 그룹 확인하기], [<]

6. **앱/서비스명 표기**: 온보딩 "모락" ↔ 로그인·홈·그룹 "작심6" — 와이어프레임 내 네이밍 불일치.
7. **관리자 진입 동선**: 관리자 화면이 참여자와 같은 하단 탭바의 "관리" 탭으로 존재(화면 4 다음 경로에도 "운영관리자 홈") — 명세서는 role=ADMIN 전용(403). 일반 참여자에게 관리 탭 노출 여부/숨김 처리 기준이 어느 문서에도 없음.
8. **화면 16 문구 오타**: "위해\n운영팀이" — 개행 이스케이프 문자열이 그대로 노출(와이어프레임 데이터 오류).

### (d) 관리자 화면 존재 여부 (AD-1~AD-5 프론트 확인)

**존재함.** 24장 중 6장(19~24)이 운영관리자 섹션이며 하단 탭 "관리"로 진입.

| API | 대응 화면 | 확인 |
|---|---|---|
| AD-1 신고 목록 | 20 신고 내역 관리 (+19 최근 접수 신고) | ○ (검색은 미커버) |
| AD-2 신고 상세+이력 | 21 신고 상세 처리 | ○ (그룹 정보·메모 필드는 미커버) |
